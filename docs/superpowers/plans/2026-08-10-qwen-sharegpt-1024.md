# Qwen ShareGPT 1024/1024 Repair Plan

> **For agentic workers:** REQUIRED SUB-SKILL: use systematic debugging, TDD, and independent review. Preserve the existing branch history and never reset or clean the worktree.

**Goal:** Make `hxinfer` run Qwen2.5-7B-Instruct with a fixed ShareGPT ChatML prompt of exactly 1024 input tokens and generate 1024 tokens without CUDA memory errors, NaN/Inf logits, or single-token collapse.

**Architecture:** Keep the existing batch-prefill and GQA implementation. Fix the proven Q/K/V bias-broadcast and decode-shape defects at the attention boundary, then drive the benchmark from a deterministic HuggingFace-tokenized fixture. Do not refactor the QKV projection API or change tokenizer, RoPE, sampling, or KV-cache architecture in this repair.

**Tech stack:** C++17, CUDA 12.8, cuBLAS, Qwen2.5-7B-Instruct, CMake, Compute Sanitizer.

## Proven root cause

Compute Sanitizer log `/tmp/hxinfer_rootcause_san_20260810105802.log` records 100 invalid global reads in the first Qwen serial forward. Every saved stack is:

```text
add_bias_fp16_kernel
-> add_bias_cuda_fp16
-> AttentionLayer::forward
-> TransformerLayer::forward
-> CausalLMModel::forward
```

Qwen uses Q width 3584 and K/V width 512. `AttentionLayer` currently calls a non-broadcast kernel that evaluates `bias[idx]` over multi-row tensors, reuses the Q element count for K, and reshapes decode buffers only after bias. Consequently:

- Prefill Q reads beyond a 3584-element bias after row 0.
- Prefill K is processed as `S*3584` instead of `S*512`, causing invalid bias reads and out-of-bounds data writes.
- Decode's first forward traverses constructor-sized or prior-prefill shapes before reshaping to one row.
- The later NaN-to-zero clamp masks downstream corruption and cannot repair it.

The tokenizer, RoPE, warmup, argmax, and output decoding occur outside or after the first illegal access and are not the primary cause.

## Chosen design

1. At entry to CUDA decode attention, reshape Q to `{1, dim}`, K/V to `{1, kv_dim}`, and attention output to `{1, dim}` before projection, clamp, or bias.
2. Apply bias with row broadcasting for Q, K, and V independently:
   - Q: total `Q.total_elements`, width `dim`
   - K: total `K.total_elements`, width `kv_dim`
   - V: total `V.total_elements`, width `kv_dim`
3. Use the existing broadcast CUDA wrappers for both FP16 and FP32. Never reuse Q's total for K or V.
4. Remove the attention-path NaN-to-zero clamps so a remaining numerical defect is observable.
5. Add a focused CUDA bias-broadcast regression target with guard coverage, plus Qwen serial/batch integration checks.
6. Replace repeated `Hello world` benchmark input with the fixed 1024-ID fixture. Do not insert BOS; the fixture already contains official ChatML framing.
7. Remove the five semantic warmup decode steps from correctness output. Record generated token IDs and full decoded output, with input and output lengths validated against `config.seq_len`.
